Diagnosis — why A0 sat at 0 and refused to trigger

Two faults, stacked. (1) 4046 DEMOD follows VCOIN, and VCOIN was left floating → A0 is 0 V. (2) Firmware asked for A0 > 600 → zero can never fire the alarm.

On a CD4046, pin 10 (DEMOD) is not an independent detector output. It is a source-follower of pin 9 (VCOIN). Your ERC report listed UNDRIVEN: U1,VCOIN and that was treated as harmless. It is not harmless if A0 is reading DEMOD.

The coil, LM358 and RV1 can all be alive on the sheet. None of that voltage reaches Arduino A0 unless it is fed into VCOIN (or you jumper the pot wiper straight to A0).

WAS VCOIN pin 9 floating → DEMOD 0 V → analogRead = 0 → (0 > 600) = false → silent
NOW FIRMWARE analogRead ≤ 40 → METAL → if no badge → D2 + D4
NOW WIRING RV1 wiper → VCOIN pin 9, DEMOD pin 10 stays on A0
// old, cannot fire when A0 is 0

Do this in Proteus, click by click

StepAction
1Stop the simulation. Double-click the Uno → Program File → load firmware/metal_gate_detector.ino.hex (export from Arduino IDE first).
2Wire RV1 wiper to 4046 pin 9 (VCOIN). Leave DEMOD → A0 as it is.
3Optional but fast: if DEMOD still stays 0 V, delete that wire and jumper RV1 wiper directly to A0.
4Play. Double-click Virtual Terminal. If A0 is 0 you must see [A0=0 TRIGGER] and the red LED.
5Sweep RV1. Numbers on the A0= line must move. Ground end = trigger. Raised = clear.
6Type A1B2C3 while A0 is 0 — alarm suppresses for 5 seconds (authorized checkout).
